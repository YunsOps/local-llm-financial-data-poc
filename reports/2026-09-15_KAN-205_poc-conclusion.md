# 비트코인 자료 해석 PoC의 설정별 결과와 적용 판단

## 상황

외부 LLM API가 담당하던 시장 및 계좌 자료 해석을 개인 노트북의 로컬 모델로 옮기는 과정에서, 최종 답변이 나오지 않거나 수치 및 출처를 잘못 설명하는 문제가 발생했다. 이 프로젝트는 실제 자동매매 수익성을 평가하는 대신, 같은 가상 자료를 받은 모델이 필요한 사실과 과거 기록을 정확히 설명할 수 있는지 확인하는 PoC로 범위를 정했다.

짧은 생성 한도와 temperature 0에서의 결과만으로 모델의 한계를 단정하지 않기 위해, 기존 영문 10문항과 채점 기준을 유지한 채 공식 권장 설정의 비추론 및 추론을 비교했다. 실제 실행 날짜는 2026-09-16이며 이전 설정의 기록은 하단에 구분하여 보존했다.

## 과제

- 정상 JSON 반환, 필수 사실 설명, 거래 제한, 회고와 시간 및 자원 사용량의 분리
- Qwen/Qwen3.5-9B와 google/gemma-4-12B-it의 같은 문항 비교
- 공식 권고와 운영자가 정한 문맥, 생성 및 시간 한도의 구분
- 관측된 성과, 여전히 남은 오류와 실제 도입에 필요한 증거의 구분

## 행동

각 모델에서 영문 10문항을 비추론 및 추론으로 한 번씩 실행하여 본 시험 40회, 워밍업은 별도로 4회를 기록했다. Qwen은 일반 과제 권장 샘플링과 문맥 창 131,072 및 생성 한도 32,768을 사용했다. 문맥 창은 Serving 절의 권고, 생성 한도는 Best Practices의 권고이다. Gemma는 공통 샘플링 권고에 문맥 창 32,768과 생성 한도 16,384를 적용했다. Gemma의 두 길이 값은 실행을 확인한 운영자 설정이며 공식 권장값이 아니다.

같은 모델의 두 모드는 길이 한도를 같게 맞췄다. Qwen의 샘플링 값은 모드별 권고에 따라 달라지므로 추론 여부만의 효과를 분리한 실험은 아니다. 한 모델씩 로딩하고 호출 후 해제했으며, 응답 시간에 로딩을 포함했다. 실제 입력과 추론, 최종 답변 및 평가 근거는 [비추론 및 추론 비교 보고서](2026-09-15_KAN-202_local-poc.md)에 보존했다. 판정의 경계 사례는 [사실 정확성과 회고 검토 보고서](2026-09-15_KAN-203_review.md)에서 확인할 수 있다.

### 이번 관측으로 말할 수 있는 결론

**공식 권장 설정에서는 두 모델 모두 10문항의 추론을 끝내고 최종 JSON을 반환했다.** 이전의 답변 부재를 두 모델의 전반적인 능력 부족으로 일반화할 근거는 부족하다. 다만 여러 설정이 함께 달라졌으므로 정상 완료의 원인이 생성 한도 하나였다고 확정할 수도 없다.

필수 사실 충족률은 Qwen 추론 90.0%, Gemma 추론 93.3%로 각 비추론보다 높았다. 내용 정확성을 우선 보면 Gemma가 한 항목 앞섰고 회고는 11/12로 Qwen의 10/12보다 높았다. 반면 Qwen은 추론 10회 모두 300초 이내, Gemma는 6회만 300초 이내였다. 따라서 품질과 응답 시간에서 같은 후보가 일관되게 우세하지 않았으며, Gemma를 모든 운영 조건에서 더 적합하다고 표현하지 않는다.

비추론의 내용 오류는 생성 한도 소진으로 설명되지 않았다. 실제 생성은 Qwen 최대 534, Gemma 최대 416토큰이었고 모두 stop으로 끝났다. 추론은 실제 생성량이 각각 최대 8,680과 9,155토큰으로 늘었으나, 최종 답변의 일부 설명 누락과 부가 주장 오류는 남았다.

### 도입 판정

이전 2026-09-15 비추론은 모델당 20응답 60항목에서 Qwen 36/60, Gemma 50/60으로 사전 기준 54/60에 미달했다. 이 결론은 그 설정에 적용된다. 이번 권장 추론의 27/30과 28/30을 두고도 동일하게 정확성 미달이라고 쓰는 것은 부정확하다.

다만 이번 조건은 문항별 한 번으로, 기존 도입 판정이 요구한 두 번 반복의 20응답을 확보한 것은 아니다. **현재 관측에서는 정확성 개선을 확인했으며, 기존 절차에 따른 도입 통과 판정은 유보한다.** 임의로 합격 기준을 강화하거나 미달로 바꾸는 것이 아니라, 서로 다른 반복 수와 설정의 증거를 구분하는 판단이다. 본 PoC에서 실제 주문과 수익률은 측정하지 않았으므로 자동매매 도입을 승인하는 결과도 아니다.

후속 검토 대상으로 Gemma를 선정한 이전 근거는 비추론에서 상대적으로 높은 사실 및 회고 점수였다. 권장 설정에서는 품질 검토의 참고 후보로 Gemma를 유지할 수 있으나, 300초 운영 요구가 중요할 때는 Qwen 추론의 완료 기록을 함께 비교해야 한다. 이번 한 번의 관측으로 모델의 우열을 영구적으로 고정하지 않는다.

### 남아 있는 한계

- Qwen의 마지막 회고 문항은 추론 중 확인한 수량과 비용 일부를 최종 답변에서 생략
- Gemma의 손익 문항은 추론의 계산식을 최종 설명으로 전달하지 못했고, 취소 주문 문항은 생성 시각을 취소 시각으로 오인
- 두 추론 조건 모두 중앙값 60초 이내 선호 조건 미충족, Gemma는 네 문항에서 300초 초과
- Qwen은 큰 문맥 창을 적용한 실행에서 일부 CPU 분산 적재를 포함, 모델 간 동일 자원 예산의 속도 비교와 구분
- 문항별 1회, 고정된 실행 순서, 실행 중 기록 조회와 검토 병행, 부하 및 열 상태의 완전한 통제 없음
- 짧은 가상 자료와 지정한 30개 사실 항목의 평가, 입력 전체 정보 손실률 또는 모든 문장의 정확도 측정과 구분
- Codex의 원본 대조 검토, 사람의 독립 검토와 구분

Luna의 이전 다섯 문항 결과는 해당 [외부 API 비교 보고서](2026-09-15_KAN-204_cloud-poc.md)에 보존했다. 이번에 Luna를 다시 호출하지 않았고 로컬 40회의 집계에 합산하지 않았다. 이전 API 비용을 이번 로컬 실행 비용으로 사용하지 않았으며, 로컬 전력 비용은 측정하지 않았다.

# KAN-205 비트코인 자료 해석 PoC 결과와 모델 선정

두 로컬 후보 모두 사전 정확성 기준에 미달하여 현재 조건의 도입을 보류합니다. 두 후보 중 후속 검토에 더 적합한 모델은 **google/gemma-4-12B-it**입니다. 같은 영문 사례에서 Gemma는 필수 항목 50/60, Qwen은 36/60을 충족했지만, Gemma에도 잘못된 매수 가능 여부와 수치 비교 등 추가 설명 오류가 남았습니다. 응답을 그대로 자동 판단에 사용하는 데 필요한 신뢰성을 확보하지 못한 결과입니다.

## S. 문제와 사용 환경

처음에는 로컬 언어 모델의 비트코인 매매 판단을 실제 거래로 이어가는 구상을 했습니다. 그러나 입력 규모와 응답 완료 여부뿐 아니라, JSON을 반환한 답변에서도 수치와 시각 및 잔액의 해석 문제가 확인됐습니다. 따라서 이번 프로젝트는 **구조화된 시장 및 가상 계좌 자료를 텍스트로 전달했을 때, 모델이 필요한 사실을 정확히 설명할 수 있는지** 확인하는 PoC로 범위를 줄였습니다.

실험 장비는 ASUS ROG Zephyrus G14, AMD Ryzen AI 9 HX 370, 설치 RAM 64 GB, NVIDIA GeForce RTX 5070 Ti Laptop GPU입니다. GPU 총량은 12,227 MiB, 드라이버는 610.88, OS는 Windows 11 10.0.26200, Python은 3.12.13, Ollama는 0.33.3입니다.

이 조건에서 실행 가능한 모델 가운데 공개 평가 점수와 특성, 라이선스 및 설치 조건을 확인해 Qwen/Qwen3.5-9B와 google/gemma-4-12B-it을 후보로 두었습니다. 기존 선정 당시 AA 지능 점수와 지시 준수 및 긴 문맥 관련 점수를 참고한 근거는 [후보 선정 보고서](2026-09-15_KAN-199_model-selection.md)에 정리했습니다. 공개 점수는 초기 후보를 좁히는 근거이며, 이번 비추론 및 양자화 조건의 성능을 보증하지 않습니다. 전체 공개 모델 중 정확한 상위 두 개라고 주장하지 않았습니다.

### 용어와 평가 범위

**가용 잔액**은 새 주문에 사용할 수 있는 금액이고, **주문에 묶인 잔액(locked)**은 기존 미체결 주문에 예약되어 바로 쓸 수 없는 금액입니다. **회고**는 이전 설명을 당시 자료와 실제 체결 및 손익에 대조하는 작업입니다. 매매가 성공했는지를 뒤늦게 평가하는 것과 구분합니다. EMA는 입력으로 제공한 지수이동평균이며, 이번 시험에서는 모델이 이를 직접 계산하도록 요구하지 않았습니다.

## A. 시험 설계와 실제 실행

### 범위를 정한 이유

- 기존 코드의 영문 지시 구조를 참고하고, 숫자를 검산할 수 있는 가상 사례 10개로 제한.
- 정상 잔고, 시간 단위가 다른 지표, 최소 주문 경계, 시각 경계, 자료 누락, 호출 실패, 체결 후 평가이익, 취소 주문과 잘못된 과거 설명을 포함.
- 자료 전체를 설명하라는 장문 요구 대신 문항마다 확인할 세 가지 사실을 지정.
- 영어 입력을 본 비교로 사용하고, Q03과 Q06 및 Q10만 의미를 맞춘 한국어 조건으로 추가.
- 두 언어 모두 영어 답변을 요구하여 입력 언어와 출력 문체의 변경을 함께 비교하지 않는 구성.

Luna는 gpt-5.6-luna, reasoning.effort=none, max_output_tokens=2048, temperature=0, JSON Schema 및 300초 제한으로 실행했습니다. 로컬의 seed와 GPU 설정을 Cloud에 전달하지 않았으므로 내부 계산까지 동일한 조건으로 보지 않았습니다.

**Gemma의 필수 항목 오류 0은 전체 답변에 오류가 없다는 뜻이 아닙니다.** 별도로 소수 단위 매수를 불가능하다고 설명한 오류 6건과 크기 비교 오류 8건이 기록됐습니다. 같은 오류가 두 반복에 나타나므로 서로 다른 14개 상황에서 발견됐다는 의미도 아닙니다. 원문과 사례별 발생 위치를 함께 확인해야 합니다.

JSON 성공률은 스키마를 적용한 실행 조건에서 얻은 결과입니다. 자유로운 대화에서도 같은 형식을 지킨다고 일반화하지 않았습니다. 허용된 hold를 반환해 거래 제한 검사를 통과했어도, hold를 선택한 이유가 맞는지는 별도 문제입니다.

### 두 모델이 놓친 사실과 성공 사례

| 사례 | 원본 및 요구 | 실제 결과와 의미 |
| --- | --- | --- |
| Q03 시간 단위 구분 | 시간봉 101,000,000 > EMA 100,000,000, 일봉 100,000,000 < EMA 102,000,000. 거래량 200→300 BTC | Qwen은 시간봉에 다른 수치를 사용하고 크기 관계도 뒤집음. Gemma는 관계를 맞혔지만 거래량과 일부 시각 설명 누락 |
| Q04 최소 주문 | 가용 4,999원, 수수료 포함 필요 현금 5,002.5원 | Qwen은 약 4,997.5원이 5,000원을 넘는다고 설명. Gemma는 미달을 설명했지만 수수료 반영 계산 누락 |
| Q01 소수 단위 매수 | 현금 100만원, 최소 주문 5,000원 | Gemma는 BTC 한 개 가격보다 현금이 적어 매수 불가라고 설명. 필수 사실 3개를 맞힌 응답에도 잘못된 실행 근거가 존재 |
| Q08 체결 후 이익 | 0.005 BTC, 매수가 1억원, 현재 1억100만원, 수수료 250원 | Gemma는 평가이익 5,000원, 비용 후 4,750원과 청산 완료 손익 0, 가상 청산 수수료 미포함까지 설명하여 3/3 |
| Q07 실패 회고 | timeout과 최종 응답 null, 실제 결정 및 체결 없음 | 두 모델 모두 실패한 호출에서 존재하지 않는 매매 결과를 회고할 수 없다는 필수 사실 설명 |
| Q10 과거 설명 정정 | 과거 100,000,000 > 102,000,000이라는 잘못된 주장 | 두 모델 모두 과거 비교를 정정했지만 체결 수량이나 평가 가격을 이용한 손익 검산 근거 일부 누락. Gemma는 추가 설명에서 현재 봉의 크기 관계를 다시 뒤집는 오류 |

Q03에서 단순 수치 비교만 맞히는 것과 요구된 거래량 및 시각까지 빠짐없이 설명하는 것은 다른 능력입니다. 이번 점수는 후자를 포함합니다. 입력이 줄어든 사실만으로 필요한 정보가 답변에 보존됐다고 볼 수 없습니다.

### 입력 전달과 문맥 창

전체 52회에서 고정 입력과 실제 전송한 지시문 및 자료가 일치했습니다. 실제 입력 토큰과 생성 한도의 합도 모두 문맥 창 안에 들어갔고, 서버 로그의 입력 토큰 수가 응답 기록과 일치했으며 truncated=0을 확인했습니다.

따라서 **이번 짧은 고정 사례의 오류를 입력 잘림으로 설명할 근거는 없습니다.** 다만 원래 수집하던 모든 시장 자료가 손실 없이 포함됐다는 의미는 아닙니다. 이번 PoC가 정의한 짧은 자료의 전송만 확인했습니다. 장문 최대 수용량, 실제 200봉 입력의 정확성, 직렬화 방식별 차이는 시험하지 않았습니다.

영문 쪽이 더 많은 필수 항목을 포함했으나 영문에서도 오류와 누락이 남았습니다. 따라서 한국어만을 실패 원인으로 지목할 수 없습니다. 표본은 세 문항이며 두 언어의 토큰 수도 다르므로 언어 전반의 우열이나 학습 데이터 구성을 추론하는 근거로 사용하지 않았습니다.

| 모델 | 실제 응답 | 필수 항목 | 시간 평균 / 중앙값 |

Luna 사용량은 입력 5,900토큰, 출력 1,939토큰, 추론 0토큰이며, [공식 단가](https://developers.openai.com/api/docs/models/gpt-5.6-luna)와 실제 캐시 사용량으로 계산한 총비용은 **USD 0.00375315**입니다. 청구서 확정 금액과는 구분합니다. 로컬 소비전력와 전기요금은 측정하지 않았으므로 로컬 비용을 0원으로 두고 비교하지 않았습니다.

같은 자료에 Luna는 필요한 사실을 설명할 수 있었습니다. 따라서 로컬의 실패를 자료 자체가 해석 불가능했기 때문이라고만 보기는 어렵습니다. 그러나 5회 결과로 Cloud 모델 전체의 신뢰성이나 실제 거래 성능을 보장할 수는 없습니다.

## 선정과 적용 범위

| 요구사항 | Qwen | Gemma | 판단 |
| --- | --- | --- | --- |
| JSON 완료 19/20 이상 | 통과 | 통과 | 형식과 응답 완료 확보 |
| 필수 사실 54/60 이상 | 미달, 36 | 미달, 50 | 두 후보 도입 보류 |
| 반환 결정과 비율의 중대한 제한 위반 0 | 통과 | 통과 | 근거의 정확성과 별도 |
| 우선순위의 사실과 회고 정확성 | 60.0%, 75.0% | 83.3%, 91.7% | 후속 검토 후보 Gemma |
| 시간 중앙값 60초 이하 | 통과 | 통과 | 현재 짧은 자료에서 지연은 주된 장애가 아님 |
| 장비 적재 | 확인 | 확인 | 현재 문맥 창에서 모델별 단독 실행 가능 |

현재 조건에서는 자동 판단을 그대로 사용하는 도입을 보류합니다. 이후 자료 검토 보조를 개선한다면 다음 검토 대상으로는 Gemma가 더 적합합니다. 수치 계산과 잔고 및 주문 가능 여부는 코드에서 검증하고, 모델은 검증된 사실의 설명을 보조하도록 역할을 제한하는 방향이 이번 관측에 맞습니다. 이 후속 방향을 구현하고 검증한 것은 아닙니다.

이번 PoC는 두 모델이 모두 합격해야 성공하는 프로젝트가 아닙니다. 사전 요구사항과 원본 근거에 따라 도입을 보류할 수 있는 결과를 얻은 것이 프로젝트의 결론입니다. 양자화, 추론 해제, 모델 버전, 질문 구성 가운데 무엇이 오류의 주원인인지는 분리 시험하지 않았습니다.
