# 개인 노트북 환경에서의 로컬 LLM 금융 자료 해석 성능 평가

## 최종 보고서

실험 기간: 2026년 9월 15일~16일  
보고서 작성일: 2026년 9월 17일  
평가 대상: Qwen/Qwen3.5-9B, google/gemma-4-12B-it  
외부 API 비교 대상: OpenAI GPT-5.6 Luna

## 1. 평가 목적과 범위

### 1.1 평가 목적

본 프로젝트는 개인 노트북에서 실행하는 로컬 대규모 언어 모델이 비트코인 시장 자료와 가상 계좌 기록을 정확하게 해석하고, 그 근거를 지정된 JSON 형식으로 설명할 수 있는지 확인하는 개념 검증, 즉 PoC이다.

출발점은 외부 LLM API가 담당하던 시장 및 계좌 자료 해석을 로컬 환경으로 옮기는 것이었다. 로컬 실행은 외부 서비스에 자료를 전송하지 않고 모델을 호출할 수 있다는 장점이 있으나, 설치와 응답 생성이 가능하다는 사실만으로 해당 업무에 적합하다고 판단할 수는 없다. 실제 적용에 앞서 잔액과 주문 상태를 구분하는지, 서로 다른 시간 단위의 가격을 혼동하지 않는지, 손익을 설명할 때 체결 수량과 수수료를 올바르게 반영하는지 확인할 필요가 있었다.

이에 평가의 초점을 수익률에서 **주어진 사실을 읽고 설명하는 능력**으로 정했다. 동일한 가상 자료를 두 로컬 모델에 제공하고, 비추론과 추론 및 설정 차이에 따라 최종 답변의 완성 여부, 사실 설명의 충족률, 회고, 응답 시간과 자원 사용량이 어떻게 달라지는지 비교했다. 외부 API 모델에도 일부 공통 문항을 제공해 로컬 결과를 해석할 비교 자료를 확보했다.

본 보고서가 답하고자 하는 질문은 다음과 같다.

1. 약 12GB의 GPU 메모리를 가진 노트북에서 두 모델이 지정된 형식의 최종 답변을 완성할 수 있는가?
2. 답변 형식과 거래 제한을 준수한 경우에도 수치, 출처, 관측 시각과 과거 거래에 관한 설명 오류가 남는가?
3. 추론 모드와 모델별 권장 설정을 적용했을 때 설명 충족률의 개선이 관찰되며, 시간과 메모리 측면에서 어떤 부담이 발생하는가?
4. 현재 자료와 실험 규모를 기준으로 어떤 모델 및 실행 조건을 우선 검토할 수 있으며, 실제 도입 판단에는 어떤 근거가 더 필요한가?

### 1.2 평가 범위

평가 자료는 정답을 원본 수치와 계산식으로 확인할 수 있도록 구성한 가상 사례이다. 실시간 Upbit 계좌를 조회하거나 실제 주문을 전송하지 않았다. 출력의 `buy`, `sell`, `hold`는 자료 해석에 따른 의견이며, 실제 체결 결과를 뜻하지 않는다.

평가에는 JSON 형식 준수, 가용 잔액과 최소 주문금액 등 계산 가능한 제약, 필수 사실 설명, 과거 기록 검토, 시간 및 토큰과 GPU 사용량을 포함했다. 미래 가격 예측, 실제 매매 수익성, 장기 수익률과 위험도, 두 모델의 토론, 실시간 운영 안정성 및 한국어 문체 품질은 포함하지 않았다.

따라서 이번 결과를 비트코인 매매 능력의 순위나 일반적인 금융 지능의 평가로 확대하지 않는다. 또한 점수는 문항별로 지정한 사실을 얼마나 완전하게 설명했는지를 나타낸다. 모든 출력 문장의 정확도나 입력 자료 전체의 정보 손실률을 직접 측정한 값은 아니다.

### 1.3 분석 대상과 근거 자료

본 보고서는 [실험_집계.xlsx](실험_집계.xlsx)에 정리한 **로컬 여섯 조건의 80응답과 Luna 비추론 5응답, 총 85응답**을 중심으로 분석한다. 로컬 비교의 핵심은 기본 비추론, 권장 비추론과 권장 추론 사이에서 설명 충족률과 실행 부담이 어떻게 달라졌는가이다. 기본 설정 추론의 답변 미완료는 설정 변경의 필요성을 설명하는 배경으로만 다루며, 한국어 비교와 실행 준비 점검 등은 최종 비교에 포함하지 않는다.

집계표는 조건별 통계, [결과 CSV](../data/README.md)는 개별 응답과 측정값 및 판정 근거를 제공한다. 문항별 입력과 채점 기준은 [cases.json](../modules/cases.json), 공통 지시문은 [prompt.py](../modules/prompt.py)에 정의되어 있다. 이 보고서의 점수는 보존된 판정을 집계한 값이며, 점수의 변화와 감점 사유를 함께 설명한다.

## 2. 핵심 결과

기본 설정 비추론에서는 두 모델 모두 영문 20회 전부 지정 JSON을 반환했고, 반환한 의견과 비율도 계산 가능한 거래 제한을 충족했다. 그러나 필수 사실 점수는 Qwen 36/60점, Gemma 50/60점으로 사전에 정한 90% 기준에 도달하지 못했다. **답변을 정상적으로 받는 것과 그 설명이 정확한 것은 별도의 문제**로 확인됐다.

모델별 권장 설정을 반영한 추론에서는 두 모델 모두 영문 10문항의 최종 JSON을 반환했으며, Qwen은 27/30점, Gemma는 28/30점을 기록했다. 권장 비추론의 17/30점과 22/30점보다 높은 결과였다.

| 비교 조건 | Qwen 필수 사실 점수 | Gemma 필수 사실 점수 | Qwen 응답 시간 중앙값 | Gemma 응답 시간 중앙값 |
| --- | ---: | ---: | ---: | ---: |
| 기본 설정 비추론 | 36/60점, 60.0% | 50/60점, 83.3% | 12.700초 | 14.739초 |
| 권장 설정 비추론 | 17/30점, 56.7% | 22/30점, 73.3% | 19.023초 | 21.206초 |
| 권장 설정 추론 | 27/30점, 90.0% | 28/30점, 93.3% | 186.757초 | 257.727초 |

권장 설정 추론은 가장 높은 설명 충족률을 보였으나 응답 시간도 크게 증가했다. Qwen은 10회 모두 300초 이내에 지정 JSON을 반환했고, Gemma는 6회만 이 기준을 충족했다. 두 모델 모두 최종 답변에 설명 누락이나 지정 항목 밖의 부정확한 표현이 남았다.

현재 노트북에서 **300초 내 응답을 요구하는 후속 검토에는 Qwen의 권장 설정 추론을 우선 후보로 제시한다.** 지연을 더 허용하면서 필수 사실 점수를 우선하면 Gemma도 비교 가치가 있다. 다만 권장 설정은 문항별 한 번만 실행했으므로, 기존의 모델당 20회 통과 조건을 충족한 모델로 확정하지 않는다. 실제 자동매매 도입 역시 이번 결과만으로 승인할 수 없다.

## 3. 실행 환경과 후보 선정

### 3.1 노트북 실행 환경

| 항목 | 실험 당시 환경 |
| --- | --- |
| 장비 | ASUS ROG Zephyrus G14 GA403WR |
| 운영체제 | Microsoft Windows 11 Home, 빌드 26200 |
| 프로세서 | AMD Ryzen AI 9 HX 370, 12코어 24스레드 |
| 시스템 메모리 | 설치 RAM 64GB |
| GPU | NVIDIA GeForce RTX 5070 Ti Laptop GPU |

| NVIDIA 드라이버 | 610.88 |

| 주요 Python 패키지 | ollama 0.6.2, openai 3.8.0, python-dotenv 1.2.3 |

환경 버전은 실험 당시 기록이다. 현재 설치 환경의 최신 버전이나 모든 장비에서의 실행 조건을 의미하지 않는다. 의존성의 구체적인 버전은 저장소의 `uv.lock`에서도 확인할 수 있다.

### 3.2 후보를 두 모델로 좁힌 이유

후보 선정에서는 먼저 노트북의 GPU 메모리와 Ollama 실행 가능성을 고려했다. GPU가 약 12GB급이므로, 모델 가중치만으로 메모리를 대부분 소진하는 대형 모델보다 양자화된 상태에서 입력 처리와 응답 생성에 필요한 공간을 확보할 수 있는 모델을 검토했다. Ollama에서 사용할 수 있는 배포 형태가 있다는 점도 조건으로 삼았다.

그다음 Artificial Analysis의 공개 종합 점수와 지시 준수, 긴 자료 활용 등의 세부 평가를 참고했다. 당시 선정 기록에서 두 모델의 AA 지능 점수는 모두 14였고, Qwen은 긴 자료 활용 지표에서, Gemma는 지시 준수 지표에서 상대적으로 높은 점수를 보였다. 서로 다른 계열을 같은 자료 해석 과제로 비교할 이유가 있었다. 다만 공개 점수의 추론 여부, 정밀도와 실행 환경은 이번 로컬 양자화 실험과 다르므로, 해당 점수를 이번 과제의 예상 정답률로 사용하지 않았다.

| 항목 | Qwen | Gemma |
| --- | --- | --- |
| 모델 전체 이름 | Qwen/Qwen3.5-9B | google/gemma-4-12B-it |
| Ollama 태그 | `qwen3.5:9b` | `gemma4:12b` |
| 양자화 | Q4_K_M | Q4_K_M |
| 당시 모델 묶음 크기 | 약 6.594GB | 약 7.557GB |
| 비교 대상으로 선정한 이유 | 실행 가능한 크기, 긴 자료 활용 능력에 관한 공개 평가 | 실행 가능한 크기, 지시 준수에 관한 공개 평가, 다른 모델 계열 |

이 과정은 모든 실행 가능한 모델을 빠짐없이 시험해 최상위 두 모델을 확정한 절차는 아니다. 공개 평가와 장비 조건을 이용해 실측할 후보를 선정한 것이다. 모델 파일 크기에는 실행 중의 문맥 캐시와 임시 작업 공간, 다른 프로그램의 GPU 점유가 포함되지 않으므로, 파일이 VRAM보다 작다는 사실만으로 모든 설정에서 실행 가능하다고 판단하지 않았다.

## 4. 시험 자료와 응답 요구사항

### 4.1 가상 자료를 사용한 이유

전체 과거 시세를 길게 전달하면 응답이 틀렸을 때 입력 길이, 자료 구조, 지시문과 모델 능력 중 무엇이 영향을 주었는지 구분하기 어렵다. 이번 평가에서는 오류 여부를 직접 검산할 수 있는 짧은 가상 사례를 구성했다. 잔액 확인, 가격 출처와 시각의 구분, 자료 누락과 과거 거래 검토처럼 서로 다른 상황을 나누고, 각 문항에서 반드시 설명할 사실 세 가지를 지정했다.

본 시험의 로컬 영문 입력은 서버 집계 기준 약 980~1,669토큰이었다. 모델별 토큰화와 추론 모드의 요청 처리 차이로 같은 자료라도 입력 토큰 수는 완전히 같지 않았다. 이 실험에서 사용한 짧은 입력의 결과만으로 각 모델의 최대 문맥 활용 능력을 평가하지 않는다.

### 4.2 입력의 구성

| 입력 영역 | 실제 포함한 정보 | 확인하려는 능력 |
| --- | --- | --- |
| `as_of`, `data_notice` | 판단 기준 시각, 가상 자료라는 설명, 제공하지 않은 정보의 추정 금지 | 관측 시점과 자료의 한계 인식 |
| `market_input` | 5분봉, 시간봉과 일봉의 종가, EMA, 거래량, 매수호가와 매도호가 및 각각의 시각 | 시간 단위, 가격 종류와 수치 비교 |
| `strategy_state` | 가용 및 묶인 잔액, 이전 결정, 주문, 실제 체결, 평가손익과 과거 기록 | 사용할 수 있는 자금과 과거 거래 사실의 구분 |
| `trading_rules` | 가상 수수료율 0.0005, 최소 주문금액 5,000원, 묶인 자금 사용 금지와 자료 누락 시 보류 | 계산 가능한 거래 제한의 적용 |
| `required_observations` | 해당 문항에서 반드시 설명해야 할 세 가지 사실 | 설명 범위의 명확한 지정 |

예를 들어 Q01은 가용 현금 1,000,000원, 가용 BTC 0, 묶인 잔액 0인 계좌를 제공한다. 5분봉의 종가는 100,000,000원, EMA는 99,000,000원이며 마감 시각은 2026-09-15 01:00 UTC이다. 이전 결정, 주문과 체결 기록은 모두 빈 배열이다. 모델은 현금과 BTC를 읽는 것에 더해, 가용 잔액과 묶인 잔액을 구분하고 종가가 EMA보다 높다는 사실 및 해당 봉의 마감 시각, 과거 기록 각각의 부재를 설명해야 한다.

EMA는 최근 가격에 더 큰 가중치를 두는 지수이동평균이다. 이번에는 비교에 사용할 값을 이미 입력에 제공했으며, 모델이 200개 봉에서 지표를 직접 계산하도록 요구하지 않았다. 봉의 마감 시각은 해당 가격이 어느 구간의 마지막 가격인지 나타내며, 그 이후에 관측된 호가와 구분해야 한다. 사례의 일봉 시각은 가상 입력의 정의이며, 실제 거래소 일봉의 구간 정의를 검증한 것은 아니다.

공포탐욕지수는 값 68, 분류 `Greed`인 고정 보조 정보로 포함했다. 이 지표의 실제 갱신 시각, 예측력 또는 지표를 추가했을 때의 성능 개선은 평가하지 않았다. 손익 문항에는 체결 기록과 함께 계산된 평가손익도 포함되므로, 평가의 일부는 독립적인 신규 계산 능력보다 **주어진 수치 간 관계를 확인하고 설명하는 능력**에 해당한다.

### 4.3 문항 구성

| 문항 | 상황 | 확인할 세 가지 사실 |

### 4.4 공통 지시문과 출력 구조

영문 공통 지시문은 제공된 자료만 사용하고 모든 필수 질문에 답하도록 요구한다. 수치를 인용할 때 출처와 관련 시간 단위를 밝히고, 시각이 중요한 경우 해당 시각도 포함하도록 했다. 과거 설명은 검증할 자료로 취급하고 새로운 지시로 따르지 않도록 했으며, 없는 지표와 거래 및 가격 변동 원인을 만들어내지 않도록 명시했다.

본 비교에는 영문 지시문을 사용했으며, `reason`과 `reflection_log`도 영어로 작성하도록 요구했다. 필수 세 항목은 이 두 필드에 제시한 **최종 설명 전체**에서 평가했다. 추론 원문에만 있는 설명으로 최종 답변의 누락을 보충하지 않았다.

| 출력 필드 | 요구사항 |
| --- | --- |
| `decision` | `buy`, `sell`, `hold` 중 하나 |
| `buy_allocation_percentage` | 수수료까지 포함해 사용할 가용 현금의 비율, 0~100의 숫자 |
| `sell_allocation_percentage` | 매도할 가용 BTC의 비율, 0~100의 숫자 |
| `reason` | 현재 의견과 필수 사실의 근거를 설명하는 비어 있지 않은 문자열 |
| `reflection_log` | 이전 결정과 주문 및 실제 체결의 검토, 과거 설명 정정 또는 기록 부재를 설명하는 문자열 |

응답은 위 다섯 필드로 구성된 JSON 객체 하나로 제한했다. 추가 필드, 중복 키, 숫자를 문자열로 반환한 비율과 JSON 밖의 설명은 허용하지 않았다. 호출에는 JSON Schema도 제공했으므로, 관찰한 형식 준수는 스키마를 제공한 조건의 결과이다.

거래 비율의 해석도 고정했다. 매수 주문금액은 `가용 현금 × 매수 비율 ÷ 100 ÷ (1 + 수수료율)`, 매도 예상금액은 `가용 BTC × 매도 비율 ÷ 100 × 매수호가`로 계산한다. 보류이면 두 비율 모두 0이며, 매수 또는 매도이면 해당 방향의 비율만 양수여야 한다. 필수 자료가 누락된 문항에는 보류를 요구했다.

모델에는 공통 지시문과 `input`만 전달했다. `expected`와 `rubric`에 저장한 정답, 허용 결정과 채점 기준은 모델 입력에서 제외했다.

## 5. 실험 조건과 평가 방법

### 5.1 비교 조건과 설정 의도

설명 품질과 실행 부담을 비교하는 조건은 기본 설정 비추론, 권장 설정 비추론과 권장 설정 추론이다. 기본 비추론은 짧은 생성 한도와 공통 설정에서의 결과를, 권장 비추론은 모델별 설정 변경만으로 설명이 개선되는지를, 권장 추론은 추론을 허용한 실행 조건에서의 품질과 시간 변화를 확인하는 데 사용한다.

여기서 기본 설정은 본 프로젝트에서 정한 공통 설정이며 Ollama의 모든 기본값을 그대로 사용했다는 뜻은 아니다. 권장 설정은 시험 당시 확인한 모델별 공식 안내를 반영하되, 노트북 실행을 위해 정한 문맥 및 생성 한도와 호출 제한을 포함한다.

| 조건 | 모델 | 문맥 창, 토큰 | 생성 한도, 토큰 | temperature / top_p / top_k | presence_penalty | 호출 제한 |
| --- | --- | ---: | ---: | --- | ---: | ---: |
| 기본 비추론 | 두 모델 | 8,192 | 2,048 | 0 / 0.95 / 40 | 0 | 300초 |
| 권장 비추론 | Qwen | 131,072 | 32,768 | 0.7 / 0.8 / 20 | 1.5 | 1,800초 |
| 권장 추론 | Qwen | 131,072 | 32,768 | 1.0 / 0.95 / 20 | 1.5 | 1,800초 |
| 권장 비추론 및 추론 | Gemma | 32,768 | 16,384 | 1.0 / 0.95 / 64 | 0 | 1,800초 |

로컬 공통 설정은 seed 42, min_p 0, frequency_penalty 0, repeat_penalty 1이다. Qwen 추론에는 일반 과제용 권장 샘플링을 적용했다. Qwen의 생성 한도 32,768과 문맥 창 131,072는 당시 Best Practices 및 Serving 안내를 참고한 설정이다. Gemma의 샘플링은 공식 안내를 반영했으나 문맥 창 32,768, 생성 한도 16,384는 운영자가 정한 값이다. 공식 문서에 별도 값이 없는 항목을 공식 권장값이라고 해석하지 않는다.

문맥 창은 요청을 처리할 수 있는 토큰 공간이고, 생성 한도는 응답 생성에 허용하는 최대량이다. 실제 입력이 약 1천여 토큰이라고 해서 나머지 공간을 모두 사용하거나, 큰 생성 한도를 설정했다고 해서 반드시 그만큼 출력하는 것은 아니다. 추론 모드에서는 서버가 반환한 추론과 최종 답변에 생성 예산이 사용되므로, 최종 JSON 자체가 짧더라도 답변 완성까지 더 많은 생성량이 필요할 수 있다.

기본 8,192토큰은 이번 짧은 문항을 시험하는 공통 설정이었다. 여러 문맥 길이를 동일 조건에서 비교해 최적값 또는 장비 최대값으로 선정한 것은 아니다. 권장 설정에서 문맥 창을 크게 확보한 결과 역시 해당 길이의 입력 전체를 실제로 처리했다는 증거가 아니다.

300초는 운영 요구를 판단하는 기준이고, 권장 설정의 1,800초는 답변이 끝나는지 관찰하기 위한 실행 제한이다. 300초를 넘겨 답변한 경우 1,800초 안에 정상 종료했더라도 300초 기준은 미충족으로 집계했다.

### 5.2 반복과 비교 단위

기본 비추론은 영문 10문항을 모델별 두 번씩 호출해 총 40응답을 확보했다. 권장 설정은 모델과 모드별로 같은 영문 10문항을 한 번씩 호출해 비추론 20응답과 추론 20응답을 확보했다. Luna는 사전에 선택한 공통 다섯 문항을 한 번씩 호출했다.

| 비교 구분 | 문항 및 반복 | 모델당 응답 수 | 두 로컬 모델 또는 Luna의 합계 |
| --- | --- | ---: | ---: |
| 기본 비추론 | 영문 10문항, 각 2회 | 20 | 40 |
| 권장 비추론 | 영문 10문항, 각 1회 | 10 | 20 |
| 권장 추론 | 영문 10문항, 각 1회 | 10 | 20 |
| Luna 비추론 | 공통 영문 5문항, 각 1회 | 5 | 5 |
| 분석 대상 합계 | 조건별 분리 비교 | — | 85 |

각 호출은 이전 대화를 이어받지 않는 독립 요청이다. 회고 문항도 실제 이전 실험의 답변이 아니라 문항에 고정한 과거 기록을 제공한다. 모델과 실행 조건마다 응답 수와 점수 분모를 명시하며, 서로 다른 반복 수를 가진 결과를 하나의 총점으로 합산하지 않는다.

기본 설정 추론은 문맥 8,192와 생성 한도 2,048 또는 4,096에서 최종 답변을 확보하지 못했다. 따라서 해당 조건의 낮은 설명 점수를 내용 오류로 해석하는 대신, 최종 답변의 미완료로 구분한다. 이 관찰을 바탕으로 더 큰 생성 여유와 모델별 권장 설정에서 답변 완성과 설명 품질을 확인했으며, 상세 미완료 기록은 보관된 CSV에서 확인할 수 있다.

### 5.3 형식, 거래 제한과 사실 설명의 분리 평가

형식 검사는 다섯 필드의 존재와 자료형, 허용값, 추가 필드와 중복 키를 확인한다. 거래 제한 검사는 반환한 결정과 비율을 가용 잔액, 수수료, 최소 주문금액과 자료 누락 규칙에 대조한다. 이 두 검사는 코드로 수행한다.

사실 설명은 문장을 읽고 원본 수치와 계산 관계를 대조하는 절차이다. 기존 판정은 Codex가 작성했으며, 의미를 자동 채점하는 코드가 수행한 결과가 아니다. CSV에 문항별 기대 설명, 근거 입력 경로, 실제 응답 인용, 판정과 점수 및 한국어 이유를 보존했다. 별도의 사람에 의한 교차 검토를 완료했다는 의미로 표시하지 않는다.

각 문항은 세 항목으로 구성하고, 항목마다 완전 충족이면 1점, 일부 누락 또는 오류이면 0점으로 처리했다. 수치가 맞더라도 필수 시각이나 출처 또는 계산 관계가 빠지면 `partial`, 잘못된 주장이나 핵심 설명의 부재는 `fail`로 구분했다. 최종 점수에서는 두 경우 모두 0점이지만 원인은 별도로 남겼다. 같은 항목에 옳은 설명과 모순되는 설명이 함께 있으면 완전 충족으로 인정하지 않았다.

최종 답변을 받지 못한 호출은 제공된 답변 기준으로 0/3점이지만, 이를 사실 세 가지를 틀리게 설명한 응답으로 해석하지 않는다. 평가할 결정이 없으면 거래 제한 준수 역시 판정할 수 없다. 세 필수 항목 밖에서 발견한 오류는 별도로 기록했으며, 지정 사실 점수가 높다고 해서 나머지 문장도 정확하다고 간주하지 않았다.

모델당 기본 비추론 총점은 `10문항 × 2회 × 3점 = 60점`, 권장 설정의 조건별 총점은 `10문항 × 1회 × 3점 = 30점`이다. 회고 점수는 Q07~Q10의 점수만 다시 모은 부분집계로, 각각 24점과 12점 만점이다. 이미 전체 점수에 포함된 값을 별도로 보여주는 것이므로 두 점수를 더하지 않는다.

### 5.4 통과 조건과 비교 우선순위

사전에 정한 기본 비추론의 필수 통과 조건은 모델당 20회 중 19회 이상이 300초 안에 지정 JSON을 반환하고, 필수 사실 54/60점 이상을 얻으며, 판정 가능한 반환 결정에서 중대한 거래 제한 위반이 없는 것이다. 응답 시간 중앙값 60초 이내는 선호 조건으로 두었다.

비교는 필수 조건 충족 여부를 먼저 확인한 뒤, 필수 사실 점수, 회고 점수, 응답 시간과 GPU 사용량 순서로 해석한다. 권장 설정의 27/30점과 28/30점은 비율로는 90% 기준 이상이나 문항별 반복 수가 다르다. 따라서 기존 20회 기준의 정식 통과와 구분해 후속 검토 후보를 판단한다.

### 5.5 시간, 토큰과 메모리 측정

전체 응답 시간은 모델 로딩, 입력 처리와 추론 및 최종 답변 수신을 포함한다. 사전 설치 정보 조회, 결과 파일 저장과 모델 해제 시간은 응답 시간에서 제외한다. 로딩 시간, 입력 처리 시간과 생성 시간 및 토큰 수는 서버 보고값을 별도로 기록한다. 생성 속도는 서버가 보고한 생성량과 생성 시간을 기준으로 산출한다.

GPU 전체 사용량은 `nvidia-smi`를 약 1초 간격으로 조회해 관측한 최댓값이다. 순간적인 최고 사용량을 완전히 포착한 값은 아니며, 다른 프로그램의 점유도 포함한다. 응답 후 모델 GPU 적재량은 Ollama에서 별도로 조회한 값이다. 두 측정은 대상과 시점이 다르므로 차이를 전부 모델 외 사용량이나 특정 캐시 크기로 해석하지 않는다. 시스템 RAM도 전체 사용량의 관측값이며 모델 단독 소비량이 아니다.

로컬 추론의 서버 보고 생성량은 추론과 최종 답변을 합한 값이며, 두 구간의 토큰 수를 각각 분리한 측정은 아니다. 요청한 생성 한도와 서버가 보고한 실제 생성량은 서로 다른 열에 보존하고, 실제 생성량을 분석에 사용한다.

## 6. 실험 결과

### 6.1 기본 설정 비추론: 빠른 반환과 설명 오류의 공존

두 모델 모두 20/20회 지정 JSON을 반환했고, 300초 조건과 반환 결정의 거래 제한 검사도 20/20회 충족했다. 응답 시간 중앙값은 Qwen 12.700초, Gemma 14.739초로 선호 시간 60초 이내였다.

그러나 Qwen의 필수 사실 점수는 36/60점, Gemma는 50/60점이었다. 회고 점수는 각각 18/24점과 22/24점이다. 두 후보 모두 54/60점 기준에 미달했으며, 형식과 속도만으로 업무 적합성을 판단하기 어렵다는 점을 보여준다.

Qwen에서는 BTC를 보유한 계좌를 두고 보유 포지션이 없다고 설명하거나, 매도 가능성과 매도 신호의 존재를 혼동한 사례가 있었다. Gemma에서는 가용 현금이 BTC 한 개의 가격보다 적다는 이유로 매수가 불가능하다고 설명한 사례가 있었다. 입력의 매수금액 계산식과 최소 주문 조건은 소수 단위 수량의 매수를 배제하지 않으므로, 한 개의 BTC를 살 수 있는지를 매수 가능 여부의 기준으로 삼은 설명은 부적절했다.

이러한 문장이 있어도 실제 반환 의견이 `hold`이고 비율이 모두 0이면 계산 가능한 거래 제한 검사에는 통과할 수 있다. 따라서 거래 제한 통과 수는 반환 결정과 비율에 대한 검사 결과이며, `reason`과 `reflection_log`에 적힌 모든 주장이 올바르다는 의미가 아니다.

### 6.2 권장 설정 비추론: 큰 한도만으로 해결되지 않은 정확성

권장 설정 비추론은 모델별 10/10회 지정 JSON을 반환했으며 거래 제한도 모두 충족했다. 필수 사실 점수는 Qwen 17/30점, Gemma 22/30점으로 각각 56.7%, 73.3%였다. 기본 비추론 대비 높은 설명 충족률이 관찰되지 않았다.

실제 생성량은 Qwen 187~534토큰, Gemma 154~416토큰이었다. 요청한 생성 한도 32,768토큰과 16,384토큰보다 훨씬 적은 양으로 정상 종료했다. 따라서 이 응답들의 오류와 누락을 생성 한도 소진 탓으로 설명할 근거는 없다. 큰 한도를 설정하면 비추론 답변이 자동으로 더 완전해진다는 결과도 얻지 못했다.

응답 시간 중앙값은 각각 19.023초와 21.206초로 기본 비추론보다 길었다. 다만 문맥 창과 샘플링 등 여러 설정을 함께 바꾸었고 반복 수도 다르므로, 이 차이를 특정 설정 하나의 영향으로 단정하지 않는다.

모든 문항이 개선된 것은 아니다. Qwen Q10은 2/3점에서 1/3점으로 낮아졌고, Gemma Q08은 3/3점에서 2/3점으로 낮아졌다. 따라서 전체 점수 상승을 모든 유형의 문제에서 오류가 제거된 결과로 해석하지 않는다.

응답 시간 중앙값은 권장 비추론 대비 Qwen 약 9.8배, Gemma 약 12.2배였다. Gemma의 Q01, Q02, Q08과 Q10은 300초를 넘겼으며 최대 시간은 Q01의 446.379초였다. 모든 호출이 1,800초 안에 끝났다는 사실과 300초 운영 조건의 충족 여부는 구분해야 한다.

이 결과는 충분한 생성 여유를 둔 권장 설정 추론에서 답변 완성과 설명 충족률의 개선이 관찰됐다는 증거이다. 그러나 기본 설정과 비교할 때 문맥 창, 생성 한도, 샘플링과 시간 제한을 함께 변경했다. Qwen은 권장 비추론과 추론 사이에도 temperature와 top_p가 다르다. 따라서 추론 기능 하나가 개선을 일으켰다고 확정하거나, 관측한 실제 생성량을 필요한 최소 생성 한도로 단정할 수 없다.

## 7. 종합 해석과 적용 판단

### 7.1 형식 준수만으로 설명의 신뢰성을 보장할 수 없다

최종 답변을 확보한 주 비교 85회는 모두 지정 JSON을 반환했고 계산 가능한 거래 제한도 충족했다. 그러나 로컬 비추론의 필수 사실 충족률은 56.7~83.3%에 그쳤다. JSON 파싱과 거래 규칙 검사는 응답을 후속 프로그램에서 처리하기 위한 조건이지만, 가격 출처나 계산 설명까지 검증하는 절차를 대신하지 못했다.

이 때문에 실제 적용에서는 잔액과 수수료 및 주문 가능 금액처럼 결정적으로 계산할 수 있는 값은 프로그램에서 계산하고, 모델 설명은 그 결과와 대조하는 구조가 적절하다. 모델의 자연어 설명만으로 존재하지 않는 체결을 인정하거나 주문을 실행할 근거를 생성해서는 안 된다. 이는 이번에 구현한 실제 주문 기능의 설명이 아니라 관측 오류에서 도출한 향후 적용 원칙이다.

### 7.2 생성 한도와 문맥 창은 설명의 정확성을 보장하는 값이 아니다

기본 추론에서는 생성 한도 소진으로 최종 답변이 나오지 않았고, 권장 추론에서는 더 큰 한도와 변경된 샘플링에서 답변을 완료했다. 한도와 설정의 검토가 필요하다는 근거는 확보했지만, 어떤 변수 하나가 결정적 원인이었는지는 분리하지 못했다.

반면 비추론은 한도에 크게 못 미치는 생성량으로 응답을 마쳤는데도 오류가 남았다. 따라서 모든 부정확한 답변을 출력 길이 부족으로 설명할 수 없다. 짧은 입력에서도 수치와 출처를 혼동한 사실은 입력 분량을 줄이는 것만으로 정확성이 보장되지 않음을 보여준다. 필요한 문맥 길이와 생성 예산의 최소 조합을 찾는 것은 별도 통제 실험의 과제이다.

### 7.3 회고는 과거 기록 검토이며 자기 학습의 증거가 아니다

권장 추론에서 Qwen의 회고 점수는 9/12점에서 10/12점으로 높아졌고, Gemma는 11/12점으로 같았다. 전체 점수의 개선에 비해 회고의 변화는 작았으며 문항별 설명 누락도 남았다.

이번 회고는 입력으로 제공한 과거 설명과 주문 및 체결을 검토하는 작업이다. 모델이 자신의 실제 이전 거래 경험을 기억하거나, 회고를 통해 장기간 학습해 다음 수익률을 개선했는지 평가한 것이 아니다. 평가 결과는 과거 기록의 출처와 계산 관계를 설명하는 능력의 범위에서 해석해야 한다.

### 7.4 조건별 우선순위

| 사용 요구 | 우선 검토 대상 | 판단 근거 | 남은 조건 |
| --- | --- | --- | --- |
| 로컬 실행과 300초 이내 응답을 함께 요구 | Qwen 권장 추론 | 27/30점, 10/10회 300초 내 반환 | 반복 검증, 누락 및 부가 오류 보완, GPU 여유 확인 |
| 응답 지연을 허용하고 이번 필수 사실 점수를 우선 | Gemma 권장 추론 | 28/30점으로 가장 높은 로컬 점수 | 4/10회 지연, 지정 항목 밖의 설명 오류 검토 |
| 빠른 로컬 응답을 우선 | 기본 비추론 | 중앙값 약 13~15초 | 두 모델 모두 90% 사실 기준 미달, 독립된 설명 검증 필요 |
| 외부 API 사용이 가능하고 공통 과제의 품질과 지연을 우선 | Luna 비추론 | 공통 5문항 15/15점, 중앙값 8.007초 | 제한된 문항 수, 외부 전송과 서비스 의존 및 실제 운영 비용 검토 |

이 표는 서로 다른 배점과 반복 수를 더해 만든 종합 점수표가 아니다. 실제 요구를 먼저 정한 뒤 관측 결과로 후보의 우선순위를 정리한 것이다. 로컬 최종 후보의 한 가지 이름을 제시해야 한다면 Qwen 권장 추론을 선택하되, **추가 검증을 전제로 한 후속 검토 후보**로 한정한다.

## 8. 실험의 한계

첫째, 가상 열 문항은 잔액과 시간, 출처 및 손익의 대표 상황을 분리하는 데 적합하지만 실제 시장의 데이터 누락, API 장애, 급격한 시세 변동과 장기간의 복잡한 거래 이력을 포괄하지 않는다. 짧은 입력의 성과를 실제 운영 전체로 확대할 수 없다.

둘째, 필수 사실 항목은 여러 수치와 맥락을 묶어 1점 또는 0점으로 판정한다. 시각 하나를 누락한 경우와 잘못된 숫자 비교를 한 경우가 모두 0점일 수 있으므로, 점수만으로 오류의 심각도를 비교하면 안 된다. 이에 보고서는 감점의 원인과 지정 항목 밖의 오류를 함께 설명했다. 별도 사람의 독립 채점이나 평가자 간 일치도는 측정하지 않았다.

셋째, 기본 비추론은 두 번 반복했고 권장 설정과 Luna는 한 번씩 실행했다. 기본 비추론의 동일 응답 반복은 제한된 일관성 확인이며 새로운 사례의 표본 확대가 아니다. 이번 결과에 통계적 유의성이나 일반화된 오류율을 부여하지 않는다.

넷째, 기본과 권장 설정 사이에서 여러 변수가 바뀌었다. 특히 Qwen의 권장 모드 비교는 추론 여부 외에 temperature와 top_p도 달라 단일 변수 효과를 분리할 수 없다. 생성 예산의 정확한 최솟값, 최적 문맥 길이와 12GB GPU의 절대 실행 한계는 이번 결과로 확정하지 않는다.

다섯째, 노트북의 전원, 발열, 다른 프로그램 점유를 완전히 통제한 성능 시험이 아니다. 약 1초 간격의 GPU 측정과 응답 후 적재량에는 각각의 측정 범위가 있다. 다른 장비나 서버의 처리량을 이번 숫자로 추정해서는 안 된다.

여섯째, 본 시험은 매매 수익성이나 미래 가격 예측을 평가하지 않았다. 최종 JSON의 의견이 실행 규칙에 맞는다는 사실은 그 의견이 수익성이 있거나 최선의 투자 판단이라는 의미가 아니다. 자동 주문 시스템의 도입 여부는 별도의 운영 검증을 필요로 한다.

## 9. 결론

약 12GB급 GPU를 갖춘 개인 노트북에서 Qwen/Qwen3.5-9B와 google/gemma-4-12B-it을 실행하고, 고정된 시장 및 가상 계좌 자료에 대한 JSON 응답을 받는 것은 가능했다. 그러나 기본 비추론에서 형식과 거래 제한을 모두 지켰음에도 필수 사실 점수는 각각 60.0%와 83.3%였으며, 모델 실행의 성공을 자료 해석의 정확성으로 간주할 수 없었다.

짧은 생성 한도의 기본 추론에서는 최종 답변이 완성되지 않았지만, 모델별 권장 설정을 반영한 추론에서는 두 모델 모두 열 문항의 답변을 완료했다. 필수 사실 충족률은 Qwen 90.0%, Gemma 93.3%로 높아졌다. 이는 초기 실행 결과만으로 로컬 모델의 능력을 단정하기보다 실제 요청 설정과 종료 상태를 확인해야 함을 보여준다.

동시에 정확한 설명을 얻는 데 필요한 시간과 자원도 확인됐다. Qwen 권장 추론의 응답 시간 중앙값은 약 187초, Gemma는 약 258초였고, Gemma의 네 응답은 300초를 초과했다. Qwen은 현재 장비에서 시간 요구를 충족한 후속 검토 후보이나 GPU 사용량이 전체 용량에 가까웠다. 두 모델 모두 설명 누락과 부가 오류가 남았고 권장 설정의 반복 검증도 충분하지 않아 실제 자동매매 도입을 확정할 단계는 아니다.

본 PoC의 성과는 어떤 모델이 더 높은 수익률을 낸다는 결론이 아니라, **같은 자료를 해석하는 과제에서 실행 조건에 따라 답변 완성도와 설명 충족률, 지연 및 자원 사용량이 어떻게 달라지는지 재확인 가능한 기록으로 정리한 것**이다. 이후 적용 여부를 검토할 때에는 코드가 계산 가능한 사실을 먼저 검증하고, 모델 설명의 출처와 수치 및 시각을 대조하는 원칙을 유지해야 한다. 최종 후보는 그 과정을 포함한 반복 검증을 거쳐 판단하는 것이 타당하다.

이 보고서는 목적과 조건, 핵심 결과 및 해석을 정리한 문서이다. 개별 응답의 전체 문장과 세부 측정값은 다음 자료에서 확인할 수 있다.

CSV의 한 행은 호출 한 번이다. `system_instruction`과 `input_` 열에는 실제 지시문과 개별 입력값, 다섯 출력 필드에는 최종 답변, `thinking`에는 모델이 반환한 추론 원문이 있다. `review_1_*`부터 `review_3_*`까지는 기대 설명과 판정, 인용문 및 한국어 근거를 보존한다. `json_valid`와 `trading_valid`는 자동 검사 결과이며, 설명의 사실 점수는 별도로 작성한 판정이다.

시험 당시 후보 및 설정 조사에서 참고한 외부 자료는 [Artificial Analysis 공개 모델 평가](https://artificialanalysis.ai/models/open-source/small), [Qwen 모델 카드](https://huggingface.co/Qwen/Qwen3.5-9B), [Gemma 모델 카드](https://ai.google.dev/gemma/docs/core/model_card_4)이다. 이 보고서의 실측 수치와 비용은 보존된 시험 기록에 근거하며, 외부 페이지의 현재 값과 동일하다고 가정하지 않는다.
